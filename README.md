# SDMini · 简易塔防（微信小游戏）

一个用 **Cocos Creator 3.8.x + TypeScript** 从零实现的简易塔防小游戏，玩法参考 Simple Defense：

> 敌人沿固定 S 形路径从左侧走向右侧基地；在路径两侧的空格上建造防御塔拦截它们。
> 漏怪会扣基地生命，生命归零即失败；清空全部 10 波即通关。

**零美术资源**：所有图形由 `Graphics` 程序化绘制，所有文字使用系统字体，
因此不需要任何图片、图集、字体或动画文件——首包体积只取决于引擎本身的裁剪。

---

## 1. 环境要求

| 项 | 版本 |
|---|---|
| Cocos Creator | 3.8.x（工程以 3.8.6 创建，更高版本会提示升级，按提示确认即可） |
| Node.js | 仅打包脚本时需要；编辑器自带，通常无需单独安装 |
| 微信开发者工具 | 仅构建微信小游戏时需要 |

无需安装任何第三方 npm 依赖（`node_modules` 为空）。

---

## 2. 打开与运行

1. 打开 **Cocos Dashboard** → 「项目」→「添加」，选择本目录 `SDMini`（即包含 `package.json` 的那一层）。
2. 用 Cocos Creator 3.8.x 打开工程。
   - 首次打开时编辑器会导入资源、生成 `library/`、`temp/`、`profiles/` 目录，
     并**自动为 `assets/` 下的每个文件生成 `.meta`**，这是正常现象（建议把这些 `.meta` 一并提交到版本库）。
3. 在「资源管理器」中双击打开 `assets/Scenes/Main.scene`。
4. 点击工具栏的 **预览（浏览器）** 或 **模拟器** 即可开玩。

> 场景里看不到任何游戏对象是正常的——`Main.scene` 只有一个 `Canvas` + `Camera`，
> 全部游戏内容在运行时由 `assets/scripts/Bootstrap.ts` → `systems/GameManager.ts` 用代码创建。

### 操作方式

| 操作 | 效果 |
|---|---|
| 点击空格子 | 打开建造菜单（箭塔 50 / 炮塔 100 / 冰塔 75），金币不足会置灰 |
| 点击已有塔 | 打开升级 / 出售菜单（最高 3 级；出售返还累计投入的 70%） |
| 底部「立即开始」 | 跳过剩余准备时间，立即出怪，并按剩余秒数 × 2 获得金币奖励 |
| 顶部「暂停」 | 暂停 / 继续战斗（暂停期间仍可建造、升级、出售，方便布防） |
| 顶部「1x」 | 循环切换 1x / 2x / 3x 倍速 |

### 防御塔

| 塔 | 造价 | 特点 |
|---|---|---|
| 箭塔 | 50 | 单体高频，性价比高，射程 2.2 格 |
| 炮塔 | 100 | 范围伤害，爆炸半径 0.9 格，边缘衰减至 50% |
| 冰塔 | 75 | 减速 35%（每级 +10 个百分点，持续 1.5s），射程 2.6 格 |

## 3. 构建微信小游戏

1. 菜单栏 **项目 → 构建发布**。
2. 「平台」选择 **微信小游戏**，填写小游戏 **AppID**（测试可用 `wx` 开头的测试号）。
3. 「起始场景」只勾选 `assets/Scenes/Main.scene`（本工程只有一个场景）。
4. 「设备方向」选择 **Portrait**（竖屏）。
5. 建议勾选 **分离引擎**：引擎由微信插件提供，可显著降低首包体积。
6. 点「构建」→ 构建完成后点「运行」，或用 **微信开发者工具** 直接导入 `build/wechatgame` 目录。

### 首包瘦身（Feature Cropping）

本工程只用到 **2D 渲染 + UI + 输入**，可在 **项目设置 → 功能裁剪** 中关闭以下模块：
3D 引擎、物理系统、粒子系统、骨骼动画（Spine / DragonBones）、TiledMap、
音频（当前版本无音效）、光照 / 阴影 / 天空盒 / 地形、粒子等。

> 建议直接使用编辑器的「2D 项目」预设，再按上述列表逐项确认，不要关闭 UI 与 2D 渲染相关模块。

### 屏幕适配

- 工程设置里的设计分辨率为 **720 × 1280（竖屏）**，`Fit Width` 与 `Fit Height` 均勾选。
- `Bootstrap.ts` 启动时还会显式调用一次
  `view.setDesignResolutionSize(720, 1280, ResolutionPolicy.SHOW_ALL)`，
  保证任何机型都不会裁掉顶部 HUD 与底部操作条（多余空间留黑边，背景色块已横向放大覆盖）。

## 4. 目录结构

```
assets/
├─ Scenes/Main.scene          # 唯一场景：Canvas + Camera，不含脚本组件
└─ scripts/
   ├─ Bootstrap.ts            # 启动入口（自举 + 兜底启动）
   ├─ config/                 # 数据层：全局常量 / 塔 / 敌人 / 关卡波次
   ├─ core/                   # 基础设施：事件总线 / 对象池 / 绘制工具 / 网格路径
   ├─ entities/               # 实体层：Enemy / Tower / Bullet
   ├─ systems/                # 系统层：GameManager / 波次 / 经济 / 塔 / 敌人 / 子弹 / 特效
   ├─ ui/                     # 表现层：HUD / 建造菜单 / 结算面板
   └─ platform/               # 平台适配：存档、震动
docs/                         # 设计与排期文档
```

分层依赖方向、主循环时序、命中测试与坐标换算等设计细节见
[docs/04-技术方案与工程结构.md](docs/04-技术方案与工程结构.md)。

## 5. 常用改动入口

| 想改什么 | 文件 |
|---|---|
| 初始金币 / 基地生命 / 难度曲线 / 配色 | `assets/scripts/config/GameConfig.ts` |
| 防御塔数值与升级公式 | `assets/scripts/config/TowerConfig.ts` |
| 敌人数值（血量/速度/护甲/赏金） | `assets/scripts/config/EnemyConfig.ts` |
| 路径走向 / 10 波出怪组成 | `assets/scripts/config/LevelConfig.ts` |
| 布局坐标（HUD、底部条、卡片位置） | `assets/scripts/ui/*.ts` 顶部的常量区 |

数值口径与逐波明细见 [docs/02-数值设计表.md](docs/02-数值设计表.md)。

## 7. 当前状态与已知限制

**已完成**：完整的一局游戏——建造 / 升级 / 出售、10 波敌人（3 种）、经济与基地生命、
暂停与 1x/2x/3x 倍速、提前开始奖励、胜负结算与本地存档、微信震动反馈。

**已知限制**：

- 无音效与背景音乐；
- 只有一个关卡（一条固定路径 + 10 波）；
- 排行榜未接入（当前只保存本地最佳波次 / 开局次数 / 通关次数）；
- 只监听触摸输入（桌面浏览器下引擎会把鼠标按下模拟为触摸，因此浏览器预览可正常点击）。

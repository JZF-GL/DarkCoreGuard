# SDMini 里程碑与任务拆分

> 版本：v1.0（MVP）
> 说明：全项目拆分为 5 个里程碑（M0–M4）。每个里程碑包含目标、交付物、任务清单（`- [ ]` 复选框）与验收标准。
> 任务按模块归类：**core**（事件总线 / 对象池 / 网格路径 / 程序化绘制）、**config**（塔 / 敌人 / 关卡数据表）、**entities**（Enemy / Tower / Bullet）、**systems**（GameManager / WaveSystem / EnemySystem / TowerSystem / BulletSystem / EconomySystem）、**ui**（HUD / BuildMenu / ResultPanel）、**platform**（微信适配 / 存档）。

---

## M0 立项与技术验证

### 目标

跑通微信小游戏运行环境与核心基础能力（渲染、网格、事件、对象池），验证「零美术资源 + 程序化绘制」技术路线可行。

### 交付物

- 可在微信开发者工具中启动的空白小游戏工程（竖屏、720×1280、`FIXED_WIDTH` 适配）。
- 网格渲染 Demo：9×13 网格 + 路径格高亮。
- 事件总线与对象池基础实现。

### 任务清单

- [ ] core：搭建工程骨架与目录结构（core / config / entities / systems / ui / platform）
- [ ] core：实现事件总线 EventBus（on / off / emit）
- [ ] core：实现对象池 PoolManager（acquire / release / 预热）
- [ ] core：实现网格坐标与格子 → 世界坐标换算工具（CellUtils）
- [ ] core：实现程序化绘制基础（Graphics 画矩形 / 圆 / 线，纯色节点封装）
- [ ] config：定义塔 / 敌人 / 关卡数据表结构并录入 MVP 数值
- [ ] platform：接入微信适配层（竖屏、设计分辨率 720×1280、FIXED_WIDTH）
- [ ] platform：搭建本地存档读写封装（初版，仅键值读写）

### 验收标准

- 微信开发者工具中可正常启动，界面竖屏铺满、无变形。
- 9×13 网格与 S 形路径通过程序化绘制正确显示，路径格/可建格颜色与配色方案一致。
- 事件总线可正确派发与接收事件；对象池可复用对象且无泄漏。

## M1 可玩核心循环

### 目标

实现最小可玩闭环：建塔 → 出怪 → 自动索敌开火 → 击杀 → 金币 → 波次推进。

### 交付物

- 可完整跑通单波战斗的可执行版本。
- Enemy / Tower / Bullet 三大实体与对应系统。

### 任务清单

- [ ] entities：实现 Enemy（生命、速度、护甲、路径进度、移动）
- [ ] entities：实现 Tower（等级、射程、索敌、开火冷却）
- [ ] entities：实现 Bullet（直线弹道、命中判定）
- [ ] systems：实现 GameManager（游戏状态机：准备 / 战斗 / 结算，暂停与倍速）
- [ ] systems：实现 WaveSystem（波次状态机，按波次表出怪）
- [ ] systems：实现 EnemySystem（生成、移动、路径进度、到达终点扣血）
- [ ] systems：实现 TowerSystem（索敌「路径进度最大」、开火调度）
- [ ] systems：实现 BulletSystem（子弹飞行、命中、伤害结算）
- [ ] systems：实现 EconomySystem（金币增减、击杀奖励）
- [ ] ui：实现基础 HUD（金币、基地生命、当前波次）
- [ ] ui：实现建造菜单 BuildMenu（点击空格弹出、可负担判断）

### 验收标准

- 可在空格建塔，敌人沿 S 形路径移动，塔能正确索敌并开火击杀敌人。
- 击杀敌人金币正确增加，敌人到达终点正确扣减基地生命。
- 单波可完整跑通并进入下一波准备阶段。

## M2 完整玩法与数值

### 目标

补齐 3 塔 × 3 级、3 敌人、10 波、升级 / 出售、经济与胜负结算，形成完整可通关的一局。

### 交付物

- 可完整通关 10 波、可失败可胜利的完整版本。
- 数值全部按《02-数值设计表》落地。

### 任务清单

- [ ] config：录入并校验塔升级费用/收益、敌人属性、10 波波次表、生命成长倍率
- [ ] systems：实现伤害公式（`max(攻击力 − 护甲, 攻击力 × 0.15)`）
- [ ] systems：实现炮塔范围伤害（爆炸半径 0.9 格、边缘衰减至 50%）
- [ ] systems：实现冰塔减速（35% 起、每级 +10 个百分点、持续 1.5s）
- [ ] systems：实现波次奖励与提前开始奖励（剩余秒数 × 2）
- [ ] systems：实现结算判定（基地生命 ≤ 0 失败；第 10 波清完胜利）
- [ ] ui：实现升级 / 出售菜单（卖塔返还累计投入的 70%，向下取整）
- [ ] ui：实现波次预告与「立即开始」按钮、准备倒计时
- [ ] ui：实现结算面板 ResultPanel（胜利 / 失败、到达波次、最终金币、剩余生命）
- [ ] platform：完善本地存档（最高记录 / 开关状态等）

### 验收标准

- 3 种塔均可升至 3 级，升级费用与收益与数值表一致。
- 10 波敌人编成、生命倍率、金币收支与数值表一致。
- 可达成胜利与失败两种结算，结算数据准确；卖塔返还金额正确。

## M3 表现与体验打磨

### 目标

在不引入美术资源的前提下，通过动效、反馈与手感优化提升可玩性与可读性。

### 交付物

- 打磨后的可发布候选版本（视觉 / 反馈 / 平衡）。

### 任务清单

- [ ] core：优化程序化绘制性能（合并绘制、减少重绘）
- [ ] core：实现对象池预热与回收策略调优（子弹 / 敌人 / 飘字）
- [ ] entities：补充塔开火、炮塔爆炸、冰塔减速的视觉表现
- [ ] entities：实现敌人血条（配色 `#66BB6A`）与受击反馈
- [ ] systems：调优索敌与开火节奏，消除子弹空窗与抖动
- [ ] ui：HUD 布局精修（顶部约 100px / 底部信息条约 140px）
- [ ] ui：建造 / 升级菜单的交互反馈（置灰、禁用态、点击动效）
- [ ] ui：结算面板与暂停/倍速交互打磨
- [ ] 数值：基于实机体验微调节奏（不改动既定数值口径，仅调表现与反馈）

### 验收标准

- 单局时长稳定在 5–8 分钟。
- 帧率稳定，无卡顿掉帧；大批敌人波次下表现正常。
- 关键交互（建造 / 升级 / 出售 / 开始 / 结算）均有明确视觉反馈。

## M4 微信小游戏接入与发布

### 目标

完成微信小游戏平台接入、包体优化、真机验证与提审发布。

### 交付物

- 通过微信小游戏审核并成功发布的正式版本。

### 任务清单

- [ ] platform：完善微信小游戏适配（安全区、不同屏宽、FIXED_WIDTH 验证）
- [ ] platform：接入微信生命周期（onShow / onHide，切后台暂停逻辑）
- [ ] platform：完善本地存档在微信环境的兼容与容错
- [ ] platform：包体优化与分包策略（满足主包 ≤ 4MB、总包 ≤ 8MB）
- [ ] 构建：生成体验版，进行多机型真机测试
- [ ] 构建：准备提审材料（小程序类目、截图、隐私说明等）
- [ ] 构建：提交审核并按反馈修复问题
- [ ] 构建：灰度发布并监控线上稳定性

### 验收标准

- 多机型真机运行无崩溃、无黑边、无交互错位。
- 主包 ≤ 4MB、总包 ≤ 8MB。
- 通过微信审核并成功发布，线上可正常进入对局。

## 风险与应对

| 风险 | 描述 | 影响 | 应对措施 |
|---|---|---|---|
| **微信小游戏包体限制** | 主包 ≤ 4MB、总包 ≤ 8MB 的硬性上限 | 超限无法提审 / 无法发布 | 坚持零美术资源（全程序化绘制）；将非首屏逻辑拆入分包；构建时压缩代码、剔除死代码；持续监控包体大小 |
| **小游戏无 DOM 环境** | 微信小游戏无 DOM / BOM，部分 Web API 不可用 | 依赖 DOM 的实现直接失效 | 尽早以 `platform` 层做适配封装，所有 DOM 相关能力替换为小游戏 API；M0 阶段即完成环境验证 |
| **对象池内存管理** | 子弹 / 敌人高频生成销毁，易产生 GC 抖动或对象泄漏 | 卡顿、内存上涨甚至崩溃 | 用 `PoolManager` 统一回收；预热常用对象；释放时重置全部状态（含事件解绑）；M3 专项调优回收策略 |
| **无法使用编辑器搭建场景** | 无法依赖可视化编辑器搭场景，需纯代码构建 | 场景搭建与调试成本高、易出错 | 全部场景与 UI 通过代码 + 程序化绘制构建，配置数据集中于 `config`；统一坐标与布局工具（CellUtils）降低手工布局误差 |

> **补充风险**：
> - **数值平衡风险**：10 波难度可能过难/过易 → 按《02-数值设计表》固定口径落地，M3 仅做表现层微调，M4 依据真机数据评估是否调整。
> - **平台审核风险**：类目或合规问题可能导致审核驳回 → M4 提前准备提审材料并预留修复迭代周期。
